## Remaining Work

### P1 — Usability (should do before merge)

- [ ] **Flow control enforcement**: Check `sendWindow` before sending DATA frames; send
  `WINDOW_UPDATE` to replenish receive window. Currently the windows are tracked in
  `ConnState` but not checked. Large uploads/downloads against a real HTTP/2 peer may
  stall or violate flow control.

- [ ] **Auto-connect in `Http2Pool`**: Add `Http2Pool.connect` that opens a TCP connection,
  creates an `Http2Conn`, and inserts it into the pool. Currently callers must do this
  manually. Add reconnect-on-failure logic using `tryScope`.

### P2 — Protocol completeness (nice to have)

- [ ] **`StreamResult` rename**: `responseHeaders`/`responseBody` → `headers`/`body`.
  These field names are misleading (a `StreamResult` is used for both request and
  response contexts on the server side).

- [ ] **RST_STREAM send path**: Add `Http2Conn.cancel : Http2Conn -> Nat ->{IO, Exception, Threads, Random} ()`
  for cancelling in-flight streams from the client side.

- [ ] **PING keepalive**: Background PING loop in `Http2Conn.new` to detect dead connections.

- [ ] **GOAWAY on shutdown**: Add `Http2Conn.close` that sends a GOAWAY frame before
  closing the connection. Currently the connection is closed abruptly.

### P3 — Runtime dependency (blocked)

- [ ] **ALPN negotiation**: The server currently speaks HTTP/2 on all connections
  regardless of TLS ALPN. Browsers and `curl` won't auto-negotiate. Requires a Unison
  runtime enhancement to expose ALPN selection from `ServerConfig`/`ClientConfig`.
  File a runtime issue requesting:
  - `ClientConfig.alpn.set : [Text] -> ClientConfig -> ClientConfig`
  - `ServerConfig.alpn.set : [Text] -> ServerConfig -> ServerConfig`
  - `Tls.negotiatedProtocol : TlsSocket -> Optional Text`

## Known Limitations (documented in `http2.README`)

- No ALPN negotiation — static HTTP/2 only
- Flow control tracked but not enforced
- No auto-connect / reconnect in `Http2Pool`
- No WebSocket-over-HTTP/2
